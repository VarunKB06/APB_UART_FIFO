# Implementation Notes

## 1. Source organization

- Synthesizable RTL: `rtl/apb_uart_rtl.v`.
- Stage 1 testbench: `verification/stage1_basic_functional/tb_basic.sv`.
- Stage 2 checker and wrapper: `verification/stage2_apb_protocol/`.
- Stage 3–7 regression: `verification/stage3_to_stage7_advanced_regression/tb_stage7.sv`.
- Local scripts: `verification/scripts/`.
- GitHub Actions: `.github/workflows/apb_uart_ci.yml`.

## 2. Simulation tool flow

The scripts use Icarus Verilog in SystemVerilog mode (`iverilog -g2012`) and execute the compiled simulation using `vvp`.

```bash
bash verification/scripts/run_all.sh
```

Individual commands are available through the stage-specific scripts. Review each script before changing simulator flags or top-module names.

## 3. Generated outputs

| Directory | Contents |
|---|---|
| `build/` | Compiled `.vvp` simulation executables |
| `results/` | Text simulation logs |
| `waveforms/` | VCD files generated by testbenches and manually captured PNG screenshots |

The GitHub Actions workflow uploads `results/` and `waveforms/` as a run artifact. The workflow artifact is downloadable from the corresponding Actions run; it is not automatically a permanent repository commit.

## 4. GTKWave

Example command:

```bash
gtkwave waveforms/stage3_to_stage7.vcd
```

Useful signal groups include:
- APB: `pclk`, `presetn`, `paddr`, `psel`, `penable`, `pwrite`, `pwdata`, `pready`, `prdata`, `pslverr`.
- TX: `uclk`, `uart_txd`, `tx_pop`, `tx_rdata`, `tx_full`, `tx_empty_u`, `tx_busy_u`.
- RX: `uart_rxd`, `rx_data`, `rx_valid`, `rx_full_u`, `rx_rempty`, `rx_rdata`, `rx_perr`, `rx_ferr`.
- Reset/configuration: `p_rst_n`, `u_rst_n`, `cfg_u`, `div_u`.

Signal scope/name visibility depends on the selected VCD and simulator.

## 5. Physical-design handoff boundary

The repository is currently an RTL and simulation-verification project. It does not include:
- Technology-specific Liberty timing libraries.
- LEF technology and standard-cell abstracts.
- RC extraction technology files.
- Synthesis constraints (SDC) validated for a target frequency.
- Genus synthesis scripts or Innovus floorplan/place/CTS/route scripts.
- DRC/LVS/signoff reports or GDSII output.

Before starting an ASIC implementation, obtain the correct digital standard-cell libraries and physical abstracts for the chosen PDK and process corner, confirm tool/PDK compatibility, define clocks and I/O constraints, and create a separate physical-design run directory. Do not treat a Virtuoso custom-layout technology attachment alone as proof that Genus/Innovus implementation collateral is present.
